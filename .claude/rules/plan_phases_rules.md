# Plan & Phases Rules

In this document, we outline the rules and guidelines for creating plans and managing phases during coding sessions. These rules are designed to ensure that coding efforts are organized, efficient, and aligned with the desired outcomes.

## Plans

- At the start of each coding session, create a plan outlining the steps you will take to solve the problem. This plan should be concise and focused on the core tasks required to achieve the desired outcome.
- The plan should include:
  - A brief overview of the problem and the desired outcome
  - A list of the main steps you will take to solve the problem
  - Any specific tools, libraries, or techniques you plan to use
  - A timeline for completing each step, if applicable
- Review and update the plan as needed throughout the coding session to ensure you stay on track and adapt to any new information or challenges that arise.
- **MUST** share the plan with the user before starting to code to ensure alignment and gather any additional input or requirements.
- At the end of each plan, give me a list of unresolved questions to answer if any. Make the questions extremely concise. Sacrifice grammar for the sake of concision.

## Moving Between Phases

- After completing the coding tasks outlined in the plan, review the code to ensure it meets the core principles and is fully optimized.
- **MUST** wait a confirmation from the user before moving on to the next phase (e.g., testing, deployment) to ensure they are satisfied with the code and ready for the next steps.
- If the user requests changes or improvements to the code, update the plan accordingly and repeat the coding phase until the user is satisfied with the code before moving on to the next phase.
